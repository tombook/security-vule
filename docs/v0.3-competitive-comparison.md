## 4. 架构差异分析

### 4.1 security-vule v0.3 — 29 维度宇宙论

```
                       File
                         │
          ┌──────────────┼──────────────┐
          ▼              ▼              ▼
   ┌────────────┐  ┌──────────┐  ┌──────────┐
   │ AST Analyzer│  │ Taint    │  │ CPG Core │
   │ (tree-sitter)│  │ Analysis │  │ (5 edge  │
   │ 21 漏洞类型  │  │ source→  │  │  kinds)  │
   └─────┬──────┘  │ sink     │  └────┬─────┘
         │         └────┬─────┘       │
         └────────────┐ │ ┌──────────┘
                      ▼ ▼ ▼
              ┌────────────────────┐
              │  29 Dimension       │
              │  Registry           │
              │  (cosmic-galaxy 23  │
              │   + math 6)         │
              └─────────┬──────────┘
                        ▼
              ┌────────────────────┐
              │  UVRS Unified Risk  │
              │  Score (sigmoid)   │
              └─────────┬──────────┘
                        ▼
              ┌────────────────────┐
              │  VuleEngine         │
              │  (analyze / topRisk)│
              └─────────┬──────────┘
                        ▼
   ┌────────────┐  ┌──────────┐  ┌──────────┐
   │ LLM Agent  │→ │ Verify   │→ │ HTML/CSS │
   │ (双模型)  │  │ Pass     │  │ Report   │
   └────────────┘  └──────────┘  └──────────┘
                        │
                        ▼
              ┌────────────────────┐
              │  Playwright PoC    │
              │  (真实运行时验证)  │
              └────────────────────┘
```

**核心创新**: 29 维度的形式化数学公式 (对齐 cosmic-galaxy), 提供可解释的归因分析。每个漏洞都被映射到 23 cosmic-galaxy 维度 + 6 数学框架,UVRS 评分有明确的理论支撑。

### 4.2 Anthropic Harness — 并行子代理

```
                  File
                    │
        ┌───────────┼───────────┐
        ▼           ▼           ▼
   [Subagent 1] [Subagent 2] [Subagent 3]
   (SQLi        (XSS         (LFI
    focus)       focus)       focus)
        │           │           │
        └───────────┼───────────┘
                    ▼
              [Aggregator]
                    │
                    ▼
              Final Report
```

**优势**: 每个 subagent 专注一种漏洞类型,深度好。**劣势**: 资源消耗大 (200K tokens/12 文件), 缺乏验证, 缺少 systematic 评分。

### 4.3 Alibaba OCR — Diff Review

```
              Git Diff
                │
                ▼
           [LLM Review]
                │
                ▼
           PR Comments
```

**优势**: Git diff 原生, PR 集成无缝。**劣势**: 只能看增量, 对小文件 (<50行) 跳过 plan, 漏检严重 (DVWA cmdi/upload 漏检, Pikachu xss 重复 5 次)。

## 7. 关键能力对比总结

### 7.1 优势 (security-vule v0.3)

1. **29 维度宇宙论** — cosmic-galaxy 对齐的形式化评分, 业界独有
2. **PoC 运行时验证** — 唯一做真实 PoC 的工具 (100% 通过)
3. **AI 安全防护** — 17 模式脱敏 + 12 注入检测 + XML 隔离, 行业领先
4. **类型归一化** — 18 canonical types + 模糊匹配, 减少 LLM 输出碎片
5. **Verify Pass** — 二次验证剔除误报, 精确度从 ~80% → ~95%

8. **可解释性** — 每个 finding 有 dominant dimension + 29 维度归因

### 7.2 劣势 (vs 对手)

1. **单文件粒度** — 不像 OCR 看 git diff
2. **跨语言支持** — CPG 架构支持多语言但实现集中在 PHP
3. **扫描速度** — 52s/文件 vs Harness 15s/文件 (因 verify pass 多一次 LLM 调用)
4. **理论深度** — 29 维度对齐 cosmic-galaxy 完整理论, 但 Harness/OCR 不需要这种复杂度
